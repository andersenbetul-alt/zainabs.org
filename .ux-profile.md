# UX Profile

Generated by `setup-ui-ux-skills`. All UI/UX skills in this project read this file before changing layout, copy, or interaction.

## Aesthetic reference

- **Standard:** Apple Native <!-- Linear | Stripe | Apple Native | Raycast | Notion | Custom -->
- **Notes:** Generous spacing, unified 22px radius, fluid/soft transitions, a restrained neutral-leaning palette (Purple Hope — see `docs/DESIGN.md`) rather than a saturated brand wash. Chosen over Notion because the site is card/section-driven rather than document/block-driven, and over Linear/Stripe/Raycast because this is a warm memorial and cancer-support site for a grieving, often stressed audience — density and technical coldness are actively wrong here.

## Banned anti-aesthetics

- Gratuitous glassmorphism / `backdrop-filter` without a high-contrast boundary
- Floating pastel pill badges for ordinary metadata
- Arbitrary decorative gradients and neon glowing borders
- Multi-color radial rainbow gradients on standard CTAs
- Cartoon empty-state illustrations (people waving / high-fiving) — this is a grief/cancer-support context; cartoon illustration of any kind reads as tonally wrong, not just dated
- Nested scrollbars and icon bloat inside inputs
- Fabricated "active" UI for features that don't exist yet (donation flows, membership, volunteer matching) — this is a house rule specific to ZAINAB.org, stricter than generic UI taste: every not-yet-real feature must be visibly marked as such (see `docs/DESIGN.md` → "Ses tonu ilkeleri")

## Accessibility target

- **Level:** WCAG 2.1 AA <!-- WCAG 2.1 AAA | WCAG 2.1 AA -->
- **Contrast:** > 4.5:1 for normal text, 3:1 for large text/borders. Not yet formally audited against the current Purple Hope palette end-to-end — `ux-audit` should check this, especially `--muted` (#685f78) on white/mist backgrounds and white text on `--gold` (#C6A16E) if gold is ever used as a text background.
- **Touch / focus:** Focus ring exists site-wide (`:focus-visible{outline:3px solid var(--plum-2);outline-offset:3px}`). Touch target sizing (44×44px) not yet audited on mobile nav/pill filters.

## Brand tone and microcopy voice

- **Voice:** Warm & Humancentric <!-- Utilitarian & Minimal | Warm & Humancentric | Opinionated & Direct -->
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:** Turkish-primary (TR/EN/NO switcher). Established pattern: never imply an inactive feature is live — say "henüz aktif değil" / "planlanan alan" plainly rather than hiding the gap or overselling. Credit inspiration from named organizations explicitly; never imply partnership or endorsement. See `docs/EDITORIAL_POLICY.md` for the hard rule on real people's photos/stories.

## Icon library

- **Library:** Project SVG <!-- Lucide | Heroicons | Phosphor | Tabler | Radix Icons | Remix Icon | Project SVG | None -->
- **Package / path:** `assets/icons/*.svg` (9 original illustrations: academy, care, community, donate, family, kids, life, rights, volunteer)
- **Notes:** This is a static HTML/CSS/JS site with no package manager, so an npm icon library (Lucide etc.) doesn't apply. **Known inconsistency to fix over time:** several existing homepage cards still use inline Unicode/emoji glyphs (🧭 ♡ ◎ ♧ ⌂ ↗ ✈ ✺ ❀ ⚖ ◐ ⟡) instead of the SVG set, predating the Purple Hope package. Per Agent rule 3 below, don't add new emoji glyphs — when touching an existing emoji-glyph card, prefer migrating it to a matching SVG from `assets/icons/` if one exists, or request one. Don't treat this file as declaring the migration already done.

## Agent rules

1. Read this profile before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task: new page → `page-patterns` (name the pattern before markup); layout / chrome → `viewports`; forms → `forms`; overlays → `surfaces`; loaders → `loaders`; empty views → `empty-states`; motion → `motion`. Before finishing UI, run `ux-audit`.
3. Use only the recorded icon library (or project SVG path). Do not mix icon sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog.
6. (ZAINAB.org-specific) Never style a planned/inactive feature so it looks clickable or live — see `.card.plan` in `docs/DESIGN.md` for the established pattern of disabling hover-lift on non-interactive preview cards.
